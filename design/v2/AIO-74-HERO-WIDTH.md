### ต้นเหตุ (ยืนยันตามที่ใบงานวิเคราะห์ไว้)


## 4 · ทำไมเขียนเป็น `height:min(150cqw,56vh)` ไม่ใช่ `width:100%`

ทั้งสองสำนวนให้กล่อง **เท่ากันทุกพิกเซล** — วัดแล้ว:

### ตาราง 3 · สามสำนวนของทาง A

| จอ | A1 `width:100%` (คงคำประกาศ 2:3) | A2 `height:min(150cqw,56vh)` | A2v `100vw − รางน้ำสองข้าง` |
|---|---|---|---|
| 390×844 | 358×472.6 | 358×472.6 | 358×472.6 |
| 430×932 | 398×521.9 | 398×521.9 | 398×521.9 |
| 412×915 | 380×512.4 | 380×512.4 | 380×512.4 |
| 360×800 | 328×448 | 328×448 | 328×448 |
| 360×640 | 328×358.4 | 328×358.4 | 328×358.4 |
| 320×568 | 288×318.1 | 288×318.1 | 288×318.1 |

ที่ต่างกันคือ **คำประกาศ**: ทาง A1 กล่องยังประกาศ `aspect-ratio:2/3` ทั้งที่กล่องจริงเป็น 0.7321–0.9152 ⇒ ไฟล์ CSS พูดอย่าง กล่องทำอีกอย่าง · นั่นคือ **ตระกูลบั๊กเดียวกับที่เราเพิ่งตามเก็บมาสามรอบ** ("ค่าที่ตั้งไว้แต่ผลไม่เป็นอย่างที่ตั้ง") และมันจะพาด่านที่เทียบ "ทรงที่ประกาศ vs กล่องจริง" ไปแดงโดยไม่มีทางแก้ที่ถูกต้อง

จึงเลือกสำนวนเดียวกับสาขาเดสก์ท็อป: ไม่ประกาศสัดส่วน ตั้งความสูงตรง ๆ
`150cqw` = 1.5 × ความกว้างของการ์ด (เพราะ `.hero` ถูกตั้งเป็นคอนเทนเนอร์ของตัวเอง) = ความสูงของปก 2:3 เมื่อยังไม่ติดเพดาน ⇒ **เจตนา "ปก 2:3 จนกว่าจะชนเพดาน 56vh" ยังอยู่ครบ แต่เขียนในหน่วยที่กล่องทำได้จริง**

**กฎที่ผูกไว้คือผลลัพธ์ ไม่ใช่ตัวสะกด** — ถ้า Dev เลือกสำนวน A2v (ไม่ใช้ container query) ก็ผ่านได้ ตราบใดที่กล่องวัดได้ตามเกณฑ์ §7 ทุกจอ
ข้อควรรู้ของสำนวน A2: เบราว์เซอร์ที่ไม่รู้จัก container query (ก่อนปี 2023) จะมองว่าบรรทัดความสูงใช้ไม่ได้ ⇒ กล่องถอยไปเป็น **ปก 2:3 เต็มความกว้างการ์ด ไม่มีเพดาน** (= หน้าตาแบบทาง B) ซึ่งยังเป็นหน้าที่ใช้งานได้ ไม่ใช่กล่องยุบ

## 7 · ข้อที่ขอให้ฝังเป็นด่านถาวร (ใบงานข้อ 5)

**ประโยคหลัก — ข้อที่ไม่มีใครถามมาก่อน:**

> **กล่องสื่อของฮีโร่ต้องกว้างเท่าการ์ดที่มันอยู่ (±1px) ทุกขนาดจอ และทุกสไลด์ในคารูเซล**

**ข้อคู่ที่ต้องมาด้วยกัน** — เพราะคำตัดสินนี้เลิกประกาศสัดส่วนที่สาขามือถือ ด่านที่เทียบ "สัดส่วนที่ประกาศ vs กล่องจริง" จึงไม่มีอะไรให้เทียบอีกต่อไป ข้อนี้มาแทน และแข็งกว่าเดิมเพราะเทียบกับ **การ์ด** ไม่ใช่เทียบกับค่าที่กล่องประกาศเอง:

> **ที่จอ <720px กล่องสื่อของฮีโร่ต้องสูงเท่า `min(1.5 × ความกว้างการ์ด, 56vh)` (±1px)**

หมายเหตุประกอบสำหรับคนเขียนด่าน
- วัดด้วย `getBoundingClientRect` ของ **กล่องจริง** ทั้งการ์ดและกล่องสื่อ — ห้ามอ่านจาก `getComputedStyle` เพราะบั๊กตระกูลนี้ computed style ยังสวยอยู่ตลอด
- ต้องวนทุกสไลด์ (`#hero-1..3`) ไม่ใช่ใบแรกใบเดียว
- ชุดขนาดจอต้องมีจอ **เตี้ย** อย่างน้อยหนึ่งจอ (เช่น 360×640) — ชุด 7 จอของ AIO-38 แตะสาขามือถือขนาดเดียว ซึ่งเป็นเหตุผลเชิงโครงสร้างที่บั๊กนี้รอดมาได้
- เกณฑ์นี้ **กัดจริง**: `check-aio74.mjs` §2 ย้อนกฎกลับเป็นของก่อน AIO-74 แล้วบังคับให้ข้อ ก แดงครบทั้ง 6 จอมือถือ และต้องไม่แดงที่ 6 จอเดสก์ท็อป/แท็บเล็ต

## 8 · ของเดิมสามข้อที่ต้องเปลี่ยนตาม (ถึง Dev และ CTO)

คำตัดสินนี้ทำให้สามข้อในด่าน/สัญญาใช้ไม่ได้ **ผมแจ้งเองเพราะเป็นผลของมติผม** — อ้างด้วยข้อความของข้อ ไม่ใช่เลขบรรทัด (ไฟล์พวกนี้ขยับบ่อย)

| # | ของเดิม | เกิดอะไรขึ้น | ที่เสนอ |
|---|---|---|---|
| 1 | `tools/test-layout.mjs` ส่วน 1 ข้อมือถือ: **"ปกยังเป็นสัดส่วน `--ar-poster` ทุกสไลด์"** (บังคับ 0.667 ±0.02 ที่ 390×844) | **แดงทันทีที่ Dev ลงของ** (กล่องใหม่ = 0.7575) · และนี่คือข้อที่ **บังคับให้บั๊กนี้คงอยู่** — มันถามว่ากล่องเป็น 2:3 ไหม ซึ่งกล่องที่หดทั้งสองด้านตอบว่า "ใช่" เสมอ | แทนด้วยสองข้อใน §7 |
| 2 | `tools/test-layout.mjs` ส่วน 6: **"กล่องจริงตรงกับทรงที่ประกาศ ±2%"** + ค่าคงที่ `SHAPE_MAX_UNDECLARED` (วันนี้ = 3 และคอมเมนต์เขียนไว้ว่า "ฮีโร่ **ไม่** อยู่ในรายการนี้ เพราะมันประกาศ --ar-poster ที่ <720px") · รวมถึงตาราง **ADR-001 §13.5** ที่ประกาศว่าที่วาง "ฮีโร่หน้าแรก" ขอทรง `poster` | ฮีโร่ไม่ประกาศสัดส่วนที่ขนาดจอใดอีกแล้ว ⇒ ตกไปอยู่ถัง "ไม่ประกาศทรง" ⇒ เพดาน 3 เต็ม · **ข้อสำคัญ: ที่เปลี่ยนคือ "ทรงของกล่อง" ไม่ใช่ "ไฟล์ที่ต้องโหลด"** — ที่ <720px ฮีโร่ยังต้องได้ **ปก 2:3** เหมือนเดิมทุกประการ | ปรับรายการฮีโร่ในแผนที่เป็น `declared:false` (ทรงไฟล์ยังเป็น `poster`/`wide` ตามเบรกพอยต์เดิม) + ขยับเพดานเป็น 4 พร้อมเหตุผลที่ตัวมันเอง + CTO แก้ถ้อยคำของ §13.5 ให้ตรง · ความครอบคลุมที่หายไปถูกแทนด้วยสองข้อใน §7 ซึ่งผูกกับการ์ด ไม่ใช่ผูกกับคำประกาศของกล่องเอง |
| 3 | `tools/test-layout.mjs` ส่วน 6 S5: ออราเคิลอิสระที่ **ค้นหาเบรกพอยต์ด้วยการไล่หาจุดที่ `.hero .bg` เลิกประกาศสัดส่วน** | ตายทั้งข้อ — ที่ 320px กล่องตอบ `auto` แล้ว ⇒ ข้อ "ฐานของการค้นหาเบรกพอยต์ถูก" แดง และข้อที่เทียบกับ `<source media>` ถูกข้าม (= เขียวผิดโดยการหายไป) | เปลี่ยนสัญญาณเป็น **`.hero .body` ค่า `right`**: `0px` ที่ <720px และเป็น % ที่ ≥720px · ผมวัดให้แล้วด้วยการค้นหาแบบเดียวกัน: **สลับที่ 720px เป๊ะ** (`check-aio74.mjs` §5 รันข้อนี้ทุกรอบ) · สัญญาณสำรองที่สลับที่จุดเดียวกัน: ทิศของไล่สีใน `.hero .bg::after` (180deg ↔ 95deg) |

ลำดับที่ปลอดภัย: Dev แก้ CSS + สามข้อนี้ใน **คอมมิตเดียวกัน** ไม่งั้นด่านจะแดงด้วยเหตุผลที่ไม่ใช่ของจริง
จนกว่าจะถึงตอนนั้น `assets/site.css` ยังเป็นกฎเก่า — `check-aio74.mjs` ข้อ 0 รายงานสถานะนี้เป็นช่อง **"รอ"** ไม่ใช่ช่อง "ผ่าน"

## 10 · ทำซ้ำเองได้

```
SHA=$(git rev-parse HEAD); PIN=/tmp/aio74-pin-$$; mkdir -p $PIN; git archive $SHA | tar -x -C $PIN
AIO74_TREE=$PIN AIO74_SHA=$SHA node design/v2/aio74-map.mjs      # วัด → design/v2/aio74-measured.json
AIO74_TREE=$PIN AIO74_STATE=Afinal node design/v2/aio74-frames.mjs  # ภาพ → design/v2/shots{,-jpeg}/
node design/v2/check-aio74.mjs                                   # ด่าน: ทุกข้อในเอกสารนี้ถูกวัดซ้ำ
```

ทำไมต้องปักทรีด้วย `git archive`: เวิร์กสเปซนี้แชร์กับ run อื่นที่ขยับ HEAD ระหว่างทาง ⇒ ถ้าวัดจากทรีสด เลขในเอกสารจะไม่ซ้ำ
`check-aio74.mjs` จะแดงเองถ้ากฎ `.hero .bg` ใน `v2.css` ขยับหลังวัด (ข้อ "ผลวัดเป็นของกฎตัวปัจจุบัน") ⇒ เอกสารที่ถือเลขเก่าไว้จะถูกจับได้ ไม่ใช่รอให้คนสังเกตเอง
